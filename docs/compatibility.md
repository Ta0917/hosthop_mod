# 参加前の構成確認

ホストは有効なホスト権限を取得した後、読み込まれているMODのIDとバージョン、および通常のJARファイルについてSHA-256を管理サービスへ登録します。参加者は現在のホストと照合し、一致しない場合は接続しません。自動再接続でも確認します。JAR以外からロードしたMODはバージョンで比較します。MODのダウンロードや導入はしません。

クライアント専用など照合から除外したいMODは、各自のMinecraftインスタンスの `config/hosthop/compatibility-ignore.txt` をUTF-8で作成し、MOD IDを1行に1つ記入します。`#` から始まる行はコメントです。ホストまたは参加者が指定したIDは比較対象から除外されます。ホストと参加者の双方に必要なMODは除外しないでください。自動判定はしません。

`config` フォルダー内（`config/hosthop` を除く）のファイル名とSHA-256をホストから受け取り、参加者の同名ファイルと比較します。内容は送信しません。違いがあればファイル名の一部を表示し、手動確認後に接続するか選べます。個人用設定も含まれるため、必ずしもワールド共通設定とは限りません。フォルダー外やワールドの `serverconfig` はこの比較の対象外です。過去のメンテナンスとの履歴比較や完全な変更一覧の画面は未対応です。

ファイル名とハッシュは共有ワールドの管理サービスと招待メンバーに見えます。対象は最大512ファイル、各8 MiBまでです。範囲を超えた場合やファイルを読めない場合は不完全な情報で接続せずエラーになります。機密情報が入った設定ファイルは、ハッシュから内容を推測される可能性もあります。

新しいWorkerには `maintenance_migration.sql` に加え `compatibility_migration.sql` の適用が必要です。新しいクライアントは互換性情報を提供しない旧ホストに接続しないため、全員の更新と管理サービスの更新をセットで行ってください。
