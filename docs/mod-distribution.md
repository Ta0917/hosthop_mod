# 配布MOD

ワールドの配布者（通常はオーナー）が公開したMODを、メンバーがHostHopで参加・ホストするときに自動でダウンロードして導入します。サーバーの動きにかかわるMODを更新するたびに手作業で配る必要がなくなります。

## 仕組み

- 配布者は自分のPCでEd25519の配布者キーを作り、公開鍵（`hosthop-key1:` で始まるコード）をメンバーに一度だけ送ります。秘密鍵はWindowsの暗号化ストレージに保存され、PCの外に出ません。
- 公開すると、`hosthop-publish` フォルダー内のJARが1つのZIPにまとめられて共有Driveフォルダーにアップロードされます。MOD名・バージョン・SHA-256を記した一覧が配布者キーで署名され、管理サービスに登録されます。2回目以降の公開では同じDriveファイルを上書きするので、メンバーがブラウザーで許可するのは最初の1回だけです。
- メンバーが「参加」を押すと、HostHopは最新の一覧を取得し、署名、ワールドID、版番号（古い一覧への巻き戻しを拒否）を確認します。そのうえでZIPをダウンロードし、各JARのSHA-256を一覧と照合します。
- 初めて見るMODは、名前・バージョンと配布者の確認コードを表示して導入の許可を求めます。一度許可したMODの更新は確認なしで導入されます。
- 導入したJARは `hosthop-mods/jars` に保存され、`mods` フォルダーには置きません。HostHopが `mods` に置く小さなローダー（`hosthop-mod-loader.jar`）が、起動時に `hosthop-mods/active.txt` に記載されたJARだけを、SHA-256を再確認してから読み込みます。
- MODはゲーム起動時にしか読み込めないため、更新を導入した後は「再起動してください」と表示し、参加を止めます。再起動後にもう一度参加してください。

管理サービス（Cloudflare）やDriveフォルダーを乗っ取られても、配布者キーで署名されていないMODは導入されません。逆に、配布者キーを登録したメンバーは、配布者が署名したMODをこのPC上のプログラムとして実行します。信頼できる配布者のキーだけを登録してください。

## 準備（配布者）

1. 管理サービスに `poc/d1/distributed_mods_migration.sql` を適用し、Workerを再配備します。手順は [PROVISIONING.md](../service/PROVISIONING.md) を参照してください。
2. Workerのシークレット `WORLDS_JSON` の対象ワールドに `"publisher": "<自分の識別子>"` を追加します（例: `[{"id":"shared_world","folder":"...","publisher":"host1"}]`）。識別子は招待コードの `principal` です。配布者以外のメンバーは一覧を置き換えられません。
3. HostHop画面の「配布MOD」→「自分の配布者キーをコピー」を押し、コピーされたコードと確認コードをメンバーに送ります。

## 準備（メンバー）

1. 配布者から受け取った `hosthop-key1:...` をクリップボードにコピーし、「配布MOD」→「配布者キーを登録」を押します。
2. 表示される確認コードが配布者のものと一致することを、配布者に確認します。
3. ローダーが `mods` フォルダーに追加されるので、Minecraftを一度再起動します。
4. これまで手動で `mods` に入れていた配布対象のMODは削除してください。同じMOD IDのファイルが2つあるとMinecraftが起動できないため、ローダーは `mods` に同じMODがあると配布版を読み込まず、HostHopは削除すべきファイル名を表示して参加を止めます。

登録済みのキーとは別のキーは登録できません。配布者が変わった場合は、`hosthop-mods/state.json` を手動で削除してから登録し直してください。

## MODを公開する

1. 「配布MOD」→「公開フォルダー」で開く `hosthop-publish` に、配布するJARを入れます。NeoForgeのMOD（`META-INF/neoforge.mods.toml` を含むJAR）だけが対象です。
2. 「MODを公開」を押して内容を確認します。フォルダーにないMODは配布から外れます。フォルダーを空にして公開すると、すべて取り下げます。
3. 自分の環境にも同じMODが導入されます。反映にはMinecraftの再起動が必要です。開発中のJARを `mods` にも置いている場合は、どちらか一方にしてください。

## 制限

- 上限はMOD 64個、各64 MiB、ZIP全体で512 MiBです。
- 配布できるのはMODのJARだけです。設定ファイルやリソースパックは対象外です。
- 公開の途中（Driveの上書き後、一覧の登録前）にメンバーが確認すると、ハッシュが一致せず失敗します。少し待って再度参加してください。
- 配布中のMODを取り下げても、そのMODのブロックなどがワールドに残っていると、[必要MODの確認](compatibility.md)によってホストになれません。
- 配布者キーを登録していないメンバーには何も導入されません。ほかのメンバーと構成が違う場合は、これまでどおり参加前の構成確認で警告されます。
- 実際の別PC・別Googleアカウント間での配布はまだ確認していません。ローダーによる読み込みは、開発環境のサーバー起動で確認しました。
