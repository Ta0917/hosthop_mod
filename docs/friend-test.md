# 協力者との共有ワールド検証

このテストは、最新版のプレイデータをもとにした**テスト用コピー**で行う。元の `dqm` ワールドを通常のシングルプレイから開く必要はない。コピーでの変更はテスト用Driveに保存され、元のワールドには自動反映されない。

## 事前準備

1. 協力者のGoogleアカウントをHostHopのGoogle Cloudプロジェクトのテストユーザーに追加し、Driveの「HostHopテスト」フォルダーを編集者として共有する。
2. 両者はMinecraft Java 26.2、NeoForge 26.2.0.6-betaと同じプレイ用MOD構成を使う。ホストにはe4mc 6.2.3が必要。HostHopの同じJARを各自の `mods` フォルダーに入れる。
3. 協力者には本人専用の招待コードを個別に渡す。公開したり他の参加者と共有したりしない。
4. 協力者はMinecraftのマルチプレイ画面から「共有ワールド」を開き、招待コード全文をコピーして「クリップボードの招待コードを登録」を押す。「Google Driveを連携」を押し、共有した本人のGoogleアカウントと「HostHopテスト」フォルダーを選ぶ。

## 接続とホスト交代

1. 最初のホストが「共有ワールドに参加」を押す。最新版のテスト用データがすでに存在するため、初期ワールドの欄は空欄にする。
2. ワールドが開き公開された後、協力者も「共有ワールドに参加」を押す。両者が同じワールドにいることと、目印のブロックを配置できることを確認する。
3. 最初のホストは通常の操作でワールドを退出し、保存が完了するまでMinecraftを閉じない。保存失敗や復旧が必要という表示が出た場合は交代を中止し、画面とログを残す。
4. 協力者は再接続待ち画面が出た場合はそこから戻り、共有ワールド画面の「最新データへのアクセスを許可」を押して、ブラウザーで表示された最新バックアップを選ぶ。その後「共有ワールドに参加」を押し、先ほどの目印が残っていることを確認する。
5. 最初のホストがゲストとして参加できることを確認する。自動再接続が動くかどうかも記録するが、未検証のため手動での再参加が必要になる場合がある。

エラーや通信障害が起きた場合は試行を重ねず、表示内容と発生した段階を記録して停止する。招待コード、Google認証情報、ログ内の秘密情報は公開しない。
