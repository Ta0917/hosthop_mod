# D1向け単一文の排他制御実験

本番サービスではありません。`acquire.sql`・`renew.sql` は条件付きリース取得・更新、`schema.sql`・`commit.sql` は単一INSERTとトリガーによる世代更新・操作記録を試します。取得要求の記録と現在状態を照合するSQLも候補としてありますが、認証付きAPIでの安全な再試行は未実装です。信頼できる時刻の保証、クラウド上のファイル検証、メンバー管理、分断された旧ホストの停止、容量管理もありません。このコードをデプロイしたり実ワールドの保護に使ったりしないでください。

`commit_status.sql` は確定済み操作の記録を取得します。認証と全項目の照合は呼び出し側に必要です。記録が見つからない場合、送信中の操作が後から確定する可能性があるため、それだけで未確定とは判断できません。`release.sql` は最終確定記録と一致するリースだけを解放します。

`lease_service.mjs` はリース取得・取得結果照会・更新と接続先の公開・照会に限定したローカルAPI実験です。テスト用のトークンハッシュとワールド・所有者の対応から呼び出し元を識別し、所有者をクライアントの入力から受け取りません。トークン発行・保管・取り消し、タイミング攻撃対策、レート制限、通信の保護、実環境でのD1整合性とリレー停止は未完成です。固定された実験用設定を注入する形であり、そのままデプロイしないでください。保存の確定・解放のAPIは提供していません。

`endpoint_update.sql` と `endpoint_status.sql` は接続先の公開と失効を試すSQLです。リースと更新番号で古い通知を拒否し、リース失効後は公開しません。番号は通知が発生したセッションに固定する必要があります。アドレスの正当性、通知元の本番認証、リレーへの到達性、実環境の整合性は未検証であり、実ゲームには接続していません。

ローカルAPIは現在の所有者だけに公開・失効を許し、共有ワールドのメンバーに限り公開先を返します。試験時に観察した `*.e4mc.link` の限定的な形式のみを受け入れますが、これはe4mcが利用する全形式を保証するものではなく、ドメインの所有者や通信相手の真正性を証明しません。SQL単体より厳しいこの検査を外部サービス向けの安全性保証として使うことはできません。

`wrangler.toml` はローカル検証専用のダミーIDで、Cloudflare上にリソースを作成しません。`--remote` は使いません。

検証時はWrangler 4.158.0を使用しました。例えば `npm install --prefix .tools/d1-tool wrangler@4.158.0 --no-audit --no-fund` で作業領域内に用意できます。Miniflare側はこのWranglerに含まれる5系の互換変換APIを使用しています。

ローカルWranglerを用意した環境では、`node poc/d1/run_local_probe.mjs .tools/d1-tool/node_modules/wrangler/bin/wrangler.js` で、再送・期限切れ・エラー時のロールバックを検証できます。テスト用データはGit管理対象外の `.tools/d1-runs` に残ります。

`node poc/d1/run_binding_probe.mjs .tools/d1-tool/node_modules/miniflare` はローカルMiniflareのD1バインディングで、番号付きパラメーターと同時要求を検証します。ネットワーク経由のサービスや本番D1のテストではありません。

`node poc/d1/run_worker_probe.mjs .tools/d1-tool/node_modules/miniflare` はローカルworkerd内でAPIを実行し、認証、リース取得、接続先の公開・照会と古い更新の拒否を検証します。本番にWorkerやDBを作成せず、デプロイ可能性や実環境の安全性を示すものではありません。
